# Internal Windows worker transport — 2 October 2026

Implemented `src-tauri/src/worker.rs`, with a private fixed-executable launcher, compile-time expected resource inventory, SHA-256 verification before execution, and rejection of changed/missing/unlisted files, redirected paths and unsafe relative names. Inventory/frame/file bounds match the development staging limits. The subprocess inherits only the required Windows/temp environment and System32 PATH, uses hidden-window flags and private stdio, and does not forward stderr or conversation content into logs.

Requests are sequential through a mutable worker, use fresh correlated UUIDs, and allow only health and session create/read/list. There is no generic native command for this transport; cloud methods are rejected. The worker validates parameters using its existing strict schemas. Responses have strict outer fields, matching IDs and protocol versions, exactly one result/error, bounded JSONL framing and redacted error text. The request deadline is 30 seconds; a failed transport becomes unusable, stops the owned child and is never automatically retried. Shutdown has a separate three-second confirmation deadline and reports failure rather than pretending success.

Final Rust suite: **6 passed, no skipped tests, 7.03 seconds**. A separate actual-worker save/reopen/list/read/stop repeat passed in **4.71 seconds**. Checks include wrong IDs, duplicate envelope keys, unknown fields, simultaneous result/error, null error alongside result, malformed framing, oversized and partial frames, EOF, a waiting-reader deadline, error redaction, unsafe paths and a synchronous native launch control. The real process tests use UUID-created synthetic temporary vaults; original CRLF and Tamil source text survive reopen. They verify that closed workers have no retained child/stdin/stdout handles and reject further requests. No real user vault was opened.

The checked staged inventory still matches all 109 files / 23,673,882 bytes; the development desktop executable builds successfully with the internal transport module. No interface files changed, so no new visual/actual WebView storage verification is claimed. Existing linker informational and npm user-config warnings remain unchanged.

## Failures preserved, not hidden

Early real-process runs reached startup/reopen deadlines with an owned child still alive. A direct source/frozen Python persistent-stdin comparison replied before EOF (0.437 / 0.297 seconds); the hidden-window Python launch control also passed. One isolated Rust run passed before the cleanup change, so the earlier failures cannot be described as proof of a single universal root cause.

Retaining the closed Worker object exposed incomplete cleanup: stop killed/waited but kept OS process/pipe handles. Dropping that object made the next diagnostic reopen pass. Shutdown now takes/releases all three handles even when the closed object is retained, and returns a confirmation result. A later parallel synchronous launch control also timed out; real-process tests now share the intended single-worker constraint while framing tests remain parallel. The default six-test suite and the independent repeated native flow passed after these changes. No deadline was increased, no failing test was skipped, and no security/antivirus setting was changed. General startup/performance stability remains unproven.
